# 同频 Together

**简体中文** | [English](README.en.md)

简洁的蓝白黑三栏协作网页：左侧主页、好友、文件、设置；中间是群聊、好友、工作区列表；右侧显示消息或文件。

**v0.1.0 · MIT 开源 · 自行部署 · Python 3.10+ · SQLite · 原生 JavaScript/CSS**

文档提供中英文切换，两种语言使用同一份程序；应用界面目前为简体中文。

适合本机和受信任局域网内的小团队试用。无需付费服务或第三方 Python 包；只有部署者需要安装 Python，其他成员通过浏览器访问同一个地址即可。账号、聊天与文件保存在部署者的电脑上。当前不包含多人编辑、在线运行代码或 Git 同步。

## 功能概览

| 功能 | 当前支持 |
| --- | --- |
| 团队交流 | 群聊、好友私聊、邀请与移除成员、删除好友 |
| 聊天辅助 | 回复、@ 提醒、未读、收藏、置顶、历史查找 |
| 资料管理 | 团队及个人文件夹、本群附件、上传预览下载 |
| 文件恢复 | 同名副本编号、历史版本、回收站、数据库备份 |
| 数据归属 | 每套部署独立存储，保留自己的账号和资料 |

首次使用请先看 [自行部署指南](docs/SELF_HOSTING.md) 和 [使用指南](docs/USAGE.md)。开发说明见 [CONTRIBUTING](CONTRIBUTING.md)，发布说明见 [GitHub 发布指南](docs/GITHUB_RELEASE.md)，版本记录见 [CHANGELOG](CHANGELOG.md)。

## 下载后怎么给别人用

1. 部署者在 GitHub 仓库点击 **Code → Download ZIP**，解压源码，按下文安装 Python 并启动。
2. 自己试用可双击 `start.bat`；同一局域网多人使用可双击 `start-lan.bat`。
3. 把部署电脑的地址（例如 `http://192.168.1.20:8765`）发给伙伴。伙伴只需浏览器，在这个地址注册账号，然后通过邀请链接加入工作区或群聊。
4. 全部成员连接同一套部署。各自在电脑上启动一份，会得到各自独立的账号和资料。

下载源码、上传 GitHub、后台运行 Docker 都不会让一台关机的电脑继续提供服务。当前发布的是可自行部署的软件，没有随项目提供的公共服务器或统一账号。

## 部署电脑关机以后还能用吗

| 情况 | 成员是否能继续使用 |
| --- | --- |
| 网站运行在你的电脑上，你的电脑关机、休眠、断网或服务停止 | 不能连接，不能继续聊天、上传或查看服务器文件 |
| 网站运行在持续开机的另一台电脑或服务器上，你自己的电脑关机 | 其他成员仍可连接那台部署机器使用 |
| 只关闭自己的网页，部署机器和服务仍在运行 | 其他成员可以继续使用；自己重新打开网页即可 |
| 部署机器重新开机，并用原来的数据目录启动服务 | 原账号、聊天和文件仍在，其他成员可重新连接 |

已在网页显示的文字可能暂时留在屏幕上，但本项目不支持离线协作或断网后继续同步新消息。关闭服务不会自动删除硬盘数据；删除数据库或 Docker 数据卷会导致数据丢失。普通启动脚本在重启电脑后需要重新运行。

## 启动

Windows 安装 Python 3.10+ 后，下载解压项目，双击 `start.bat`。macOS / Linux 运行 `sh start.sh`。也可直接运行：

```sh
python server.py
```

打开 `http://127.0.0.1:8765`，注册或登录后使用。首次启动是空系统，不预置实验账号、聊天或文件；未登录时显示登录入口。

局域网测试可运行 `python server.py --host 0.0.0.0`，使用本机局域网 IP 打开网站后生成邀请链接。伙伴需要访问同一服务器，防火墙需放行对应端口。本机 `127.0.0.1` 链接不能用于其他电脑。

Windows 也可双击 `start-lan.bat` 启动局域网服务。部署电脑需要保持开机并连接网络。不同人分别启动的实例不会自动同步；GitHub 托管源码，不会替你运行网站。

已准备 Docker 配置，可运行 `docker compose up -d --build`；默认仅本机可访问，使用命名卷保存数据。更多配置、停止服务和备份方法见部署指南。

## 群聊、工作区和权限

- **工作区保存项目资料**，包含共享文件和文件夹。工作区成员可以查看其中全部文件及公开群聊。
- **群聊用于讨论**，新建时可关联工作区，也可创建独立群聊。新群聊默认仅受邀成员可见；关联工作区时也能选择工作区全体成员可见。
- 群聊右上角显示关联工作区，点击直接查看文件。上传群聊附件时可选择「仅保存到本群附件库」或「添加到工作区文件库」；独立群聊只能保存到本群。本群附件仅群成员可访问，工作区共享附件对全部工作区成员开放。旧附件保持原有共享范围。
- 群主通过右上角「查看成员 → 邀请加入本群」生成 7 天有效的邀请。群邀请将授予本群访问权限；若群聊关联工作区，邀请也会授予该工作区全部文件和公开群聊的访问权限。其他仅受邀成员群聊仍需单独邀请。
- 工作区创建者可生成工作区邀请；它只授予工作区文件和公开群聊权限。
- 打开邀请后会先显示访问范围，用户点击「确认加入」后才加入。
- 群主可在「查看成员」中移除其他成员，不能移除群主。被移出后无法访问本群消息、搜索和仅本群附件，工作区文件及其他群的权限保留；工作区公开群也遵守此限制。移除会使本群已有邀请链接失效，群主重新生成邀请后可邀请对方回来。
- 旧群聊保持原先“工作区全体成员可见”的访问方式，旧消息、账号和文件保留。
- 通过注册邮箱申请添加好友，对方接受后私聊；私聊消息与附件仅双方可访问。
- 私聊右上角可删除好友，确认后双方好友关系解除，不能继续私聊、搜索记录或访问私聊附件。历史数据保留，重新添加并接受申请后恢复访问；共同群聊和工作区的权限保留。
- 「文件 → 我的文件工作区」是个人资料，仅自己可见；「团队共享」和主页工作区是共享资料。

## 聊天与查找

- 群聊、好友列表显示未读数量和 @ 提醒。点击输入框下方 @ 选择成员，也可输入 `@昵称` 后接空格或标点。
- 阅读位置保存在服务器；打开会话后优先定位最近 500 条中的未读消息。同一页面切换会话时保留滚动位置。超过最近 500 条的记录通过右上角查找。
- 工作区、群聊、好友均可置顶。列表行右侧的图钉控制个人排序；消息图钉将消息置顶给当前会话成员。
- 消息支持引用回复、代码块、个人收藏和会话置顶。悬停消息显示操作，窄屏直接显示；右上角书签打开收藏与置顶。
- 群聊、私聊支持文件附件；上传后在聊天显示文件卡片，支持预览和下载。单文件上限 10 MB，UTF-8 文本预览上限 1 MB。
- 右上角「查找记录」搜索全部历史，可组合关键词、开始/结束日期、聊天内容/文件类型；文件按名称搜索。日期使用浏览器本地时区，包含结束当天，结果分页按时间倒序加载。
- 搜索消息或引用消息可以查看前后文。聊天右上角「本群附件」打开本群附件库，可按文件名和日期筛选、预览及下载。查找的文件范围支持「本群附件库」「工作区文件库」和「本群聊天中的全部附件」；选择工作区时包含其他群共享和直接上传的全部工作区文件，不包含其他群的私有附件。聊天内容始终只查找当前群。
- 消息发送失败时保留输入，点击发送重试；消息和文件上传带重试标识，避免响应丢失后重复保存。上传失败可点击「重试上传」。连接状态显示在列表底部；聊天与活动约每 2.5 秒刷新。

## 文件整理和恢复

- 个人和工作区共享资料均支持多级文件夹。文件行右侧「…」可重命名、移动、查看历史版本、移入回收站。
- 文件夹旁「…」可以重命名和改变上级目录，不能移入自身或子文件夹。
- 上传同名文件时选择：保留两个文件（例如 `说明.md`、`说明 (2).md`，继续重复会递增编号），或更新原文件（保留旧版本）。
- 历史版本可以恢复；恢复时先保存当前内容，再生成新版本。
- 右上角回收站可以查看和恢复文件；回收站不提供永久删除。个人回收站汇总自己的文件，共享回收站限当前工作区。恢复后回到原文件夹。
- 工作区共享文件的整理权限属于全体工作区成员；独立群聊、私聊附件暂不提供文件夹整理入口。

## 数据与备份

账号、聊天、文件内容和版本都保存在**部署机器**的 `data/workspace.db`，不是每位成员的浏览器或 GitHub 仓库。包括个人文件和仅本群附件，它们只是访问权限不同，仍存储在同一部署的数据库里；文件原名是数据库里的记录，不代表项目目录中存在同名文件。密码保存为加盐哈希，不是明文；本项目不提供端到端加密，部署者应妥善保护数据库。

| 内容 | 默认保存位置 |
| --- | --- |
| 账号、好友、工作区、群聊、聊天、文件夹及访问权限 | `data/workspace.db` |
| 工作区文件、个人文件、群聊/私聊附件、历史版本及回收站内容 | 同一个 `data/workspace.db`，包含文件实际内容 |
| 自动与手动备份 | `data/backups/*.db`，每份都是包含账号和文件的数据库快照 |
| Docker 部署数据 | Compose 的 `together-data` 命名卷，容器内位置为 `/app/data`；实际卷名通常带项目名前缀 |
| 使用浏览器“下载”保存的文件 | 下载者自己电脑的浏览器下载目录 |

可用 `WORKSPACE_DATA` 环境变量设置数据目录。浏览器的登录 Cookie 只用于识别会话，不是数据备份。输入中的草稿和页面状态不应视为已保存，发送或上传成功后才以服务器记录为准。运行中的 SQLite 可能同时出现 `workspace.db-wal`、`workspace.db-shm`，请使用下述备份命令，不要只复制运行中的主数据库。不要将数据或备份提交到 Git。

服务启动时会在升级旧数据库前生成快照；服务器运行期间，每天首次启动或跨天后生成一份自动备份，保存在 `data/backups`。备份通过 SQLite 快照 API 创建并校验完整性，支持运行时备份。快照保留在本机，不自动清理；请定期复制到其他设备并关注磁盘容量。

手动备份：

```powershell
python maintenance.py backup
```

恢复前先停止服务器，然后运行（替换为实际备份路径）：

```powershell
python maintenance.py restore "data/backups/实际备份.db"
```

恢复工具会检查备份并保存恢复前快照；服务器运行时拒绝恢复。恢复后重新启动，所有账号需要重新登录。

## 验证

```powershell
python -m unittest discover -s tests -v
node --check public/client.js
node --check public/shared.js
node --check public/features.js
```

测试使用临时数据库和独立账号，覆盖权限隔离、邀请、历史搜索、私聊附件、未读位置、@提醒、重试去重、收藏、回复、文件夹、版本、回收站及备份恢复。`python tests/preview_fixture.py` 可启动只使用临时数据的浏览器测试服务（127.0.0.1:8766），关闭后释放测试数据。

## 后续公网部署

当前是本机或局域网协作版本，尚未公开部署。账号找回、邮件投递、登录限流、总存储配额、工作区成员移除及单独撤销邀请的管理入口尚未实现；不包含多人同时编辑、在线运行代码或 Git 同步。正式上线前需部署这些能力，使用 HTTPS 和正式应用服务，并将备份复制到服务器以外。HTTPS 部署时设置 `COOKIE_SECURE=1`。
